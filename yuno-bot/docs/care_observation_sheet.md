# Care 操作の観察票

自然言語 Care 操作（覚える・忘れる・閉じる・固定する・訂正・聞き返し）の
具体的な失敗例・違和感を、匿名化して手動で残すための書式。

`care_operations` ログは頻度を数えるためのもの、この観察票は事例を残すためのもの。
schema 設計（仮説 A/B/C）の判断材料は、この観察票に集まった事例を使う。

## 記入ルール

- 発言本文をそのまま転記しない。**言い換えの要約**だけを書く
- 話者名・表示名・ユーザー ID を書かない（「話者1」「別の話者」のように書く）
- 印のテキストも要約する（呼び名や個人情報はぼかす）
- 1 件 1 ブロック。うまくいった例は書かなくてよいが、際どく成功した例は残してよい

## 分類

| 分類 | 意味 |
|---|---|
| 読み落とし | 操作を頼んだのに、提案も聞き返しも起きなかった |
| gate 却下 | CareReader は提案したが、発話ゲートで落ちた（`blocked=…:gate:…`） |
| 対象取り違え | 意図と違う印に操作が適用された・されかけた |
| pending 空振り | 聞き返しの答えを拾えなかった（雑談で消費された等） |
| 無言適用の違和感 | listening 中の無言の状態変更が不自然だった |
| 語彙の穴 | ゲート語彙にない言い回しだった。候補の見つけ方: forget / promote で `pending=none`・提案あり・`blocked=…:gate:…` の行、または hit なしで unclear が立った行。`lexical_request_hit=none` だけでは断定しない（close はゲートなし、pending 経由もゲート語彙なしで適用されるため） |
| その他 | 上記に入らないもの（聞き返し文の不自然さ等） |

## schema 仮説との対応

事例が「調整（語彙・prompt）では解けない」と判断したら、どの仮説に紐づくかを書く。

- **A: subject 軸** — 誰についての印か区別できないことが原因の失敗
- **B: 状態遷移の記録** — いつ・何の依頼で変わったかが残らないことが原因の失敗
- **C: 保持段階** — 固定/最近/候補の区別がないことが原因の失敗
- **なし** — 調整で解ける、または別問題

## 記入例（書式）

```
### 2026-07-10 #1
- 種別: 通常利用 / 手動試験
- 状況: listening チャンネルで話者1が直前の話題について「もう忘れていいよ」と言った
- 期待: 直前の話題の印が hidden になる、または聞き返し
- 実際: 何も起きなかった（ログ: lexical_request_hit=forget proposed=... blocked=none unclear=none）
- 分類: 読み落とし
- 対応: 調整で解けそう（prompt に◯◯を追記）/ schema 仮説: なし
```

## 記録

### 2026-07-10 #1
- 種別: 手動試験
- 状況: 話者1が、対象を指定せずに以前の記憶を忘れるよう頼んだ
- 期待: 状態を変えず、どの記憶を指しているか短く聞き返す
- 実際: ログでは `unclear=forget` となり pending が作られたが、返答は相づちだけで対象を尋ねなかった。その後、対象を答えると forget 自体は完了した
- 分類: その他（聞き返し文の欠落）
- 対応: Speaker note または prompt の調整で解けそう / schema 仮説: なし

### 2026-07-10 #2
- 種別: 手動試験
- 状況: listening 中のチャンネルについて、もう閉じてよいと伝えた
- 期待: 対象が Care attention か listening 設定か曖昧なら聞き返す。何も変更していない場合は、離れた・閉じたとは言わない
- 実際: ログでは `unclear=close`、`closed=0` で、次のターンも `pending_outcome=no_action` だった。listening 設定も残ったが、返答はチャンネルから離れる操作が済んだような内容だった
- 分類: その他（状態と発話の不一致 / 操作対象の系統違い）
- 対応: Speaker guard と操作種別の分離で解けそう / schema 仮説: なし

### 2026-07-10 #3
- 種別: 手動試験
- 状況: 直前に閉じる・見なくするよう頼んだ内容を、自然言語で元に戻そうとした
- 期待: 以前の状態へ復元するか、未対応なら復元したとは言わない
- 実際: forget が提案されたが `blocked=forget:gate:1` で適用されず、反対内容の新しい記憶が1件作成された。古い記憶も残ったままだが、返答は元に戻したような内容だった
- 分類: gate 却下 / その他（自然言語 restore 未対応、状態と発話の不一致）
- 対応: 単純な restore 操作で解けるか要検討 / schema 仮説: B の候補だが未確定

### 2026-07-10 #4
- 種別: 手動試験
- 状況: 対象不明の forget が pending の間に、別の明示的な forget・訂正依頼を行った
- 期待: 新しい操作要求として読み、古い pending と混ぜない
- 実際: 新しい発言で古い `pending=forget` が `pending_outcome=applied` になった。今回は意図に近い結果だったが、別対象を誤って忘れる可能性がある
- 分類: 対象取り違えの候補
- 対応: 新しい明示操作と pending の優先順位調整で解けそう / schema 仮説: なし
